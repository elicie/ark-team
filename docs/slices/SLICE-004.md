- Objective: Provide an in-process TypeScript app-server session that preserves
  writer sandbox isolation, surfaces dangerous-action approval requests without
  answering them, and continues the same turn only after an explicit caller
  decision.
- Included requirements:
  - `REQ-401`: Use `codex app-server` over local stdio with the documented
    initialize, thread/start, and turn/start flow.
  - `REQ-402`: Start only PL and worker sessions, require linked Git worktrees,
    and verify the returned model, xhigh effort, workspace-write sandbox,
    user reviewer, and on-request approval policy.
  - `REQ-403`: Convert command, file-change, and permission server requests into
    a redacted `waiting_user` update without automatically accepting them.
  - `REQ-404`: Accept `approve_once`, `approve_session`, `decline`, or `cancel`
    from the caller, send the method-specific response using the original
    JSON-RPC request ID, and continue waiting on the same turn.
  - `REQ-405`: On completion, return only the session and turn IDs, final role
    report, configured role metadata, and the last reported token usage.
  - `REQ-406`: Fail closed on protocol errors, invalid decisions, timeout,
    caller cancellation, or app-server termination and close the owned child.
  - `REQ-407`: Verify that the installed Codex-generated stable TypeScript
    schema still contains every protocol method and field used by the gateway.
- Acceptance criteria:
  - `AC-401`: The client performs one initialize handshake before thread/start
    and turn/start and uses no TCP listener or development port.
  - `AC-402`: PM requests are rejected; PL and worker requests reuse the
    SLICE-003 linked-worktree guard and the thread/start response must confirm
    the exact role settings before a turn begins.
  - `AC-403`: No response is written for an approval server request before
    `decide()` is called, and only one approval may be pending per session.
  - `AC-404`: Command and file decisions map to `accept`,
    `acceptForSession`, `decline`, or `cancel`; permission approvals grant only
    the requested fields for the requested scope, while decline/cancel grant
    an empty turn-scoped profile.
  - `AC-405`: Approval IDs exposed to callers are opaque and cannot be reused
    after resolution.
  - `AC-406`: Completion returns the final observable agent message and usage
    without raw reasoning or full event history.
  - `AC-407`: Timeout and caller cancellation interrupt the active turn and
    produce a typed closed failure.
  - `AC-408`: A live probe reaches a real command approval request, declines it,
    confirms the requested outside-worktree file was not created, and receives
    a terminal report from the same thread.
  - `AC-409`: Existing tests, bundles, model checks, and official skill/plugin
    validators continue to pass.
